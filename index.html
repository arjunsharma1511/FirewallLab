Orientation

What a firewall actually does

A firewall examines network traffic and applies policy. A rule can match fields such as direction, source, destination, protocol, port, connection state and zone. The firewall then allows, denies, rejects or logs the traffic.

02

Firewall academy

The six questions for every packet

1

Direction

Inbound, outbound or between internal zones?

2

Source

Which IP, subnet, user or zone sent it?

3

Destination

Which server, address or zone receives it?

4

Protocol

TCP, UDP, ICMP or another protocol?

5

Port/service

HTTPS 443, DNS 53, SSH 22 and so on.

6

State

New connection or return traffic for an established one?

Default deny

Allow only required traffic; deny everything else. Safer than allowing broadly and trying to list every threat.

Least privilege

Use the narrowest source, destination, service and direction that meets the business need.

First match wins

Many firewalls evaluate rules top to bottom. A broad early rule can hide a later specific rule.

Stateful inspection

The firewall tracks connections and can recognise valid reply traffic.

NAT

Network Address Translation changes address information; it is not automatically a security decision.

Logging

Logs show observations and rule results. They require context and careful retention.
